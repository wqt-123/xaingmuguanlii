## Atlas PM WebApp v3 — 完整重建JS

### 问题背景
经过多次迭代修补后,Atlas PM WebApp的JavaScript部分积累了过多技术债。用户反馈点击反应失效、模块交互失败。经过系统性诊断后发现:
1. `applyTranslations()` 使用 `el.textContent = t(key)` 会破坏所有含有子元素(SVG、div)的元素
2. 部分事件监听器与HTML结构不匹配(如 `week-selector-dropdown` 不存在,实际是 `week-selector-options`)
3. 多次补丁导致代码变得脆弱且难以调试

### 解决方案
完全重写JavaScript部分(约52K字符),采用以下策略:

1. **保护性i18n** - `applyTranslations` 检测子元素,有子元素时插入 `<span>` 而非覆盖textContent
2. **健壮的事件处理** - 所有20个 onclick 函数都通过 `window.X = X` 显式导出
3. **全局错误捕获** - `window.addEventListener('error', ...)` 自动在屏幕顶部显示JS错误
4. **默认中文** - `currentLang` 初始化为 `'zh'`,登录后立即看到中文界面
5. **ID映射修复** - 修正所有错误的元素ID引用(week-selector-dropdown → week-selector-options)

### 文件结构
- `pm-webapp.html` (250KB, ~4000行) - 完整的企业级项目管理WebApp
- 默认语言:中文
- 登录凭据:admin / admin
- 5个核心页面:仪表盘、当前迭代、团队成员、周报中心、项目设置
- 完整CRUD、导出(PDF/Word/PNG)、i18n、阶段指示器

### 经验教训
- 大型HTML文件经过多次补丁后应该完全重写,而不是继续修补
- 使用 `textContent` 覆盖元素前必须检查子元素
- 事件委托应明确处理边界情况(如closest返回null)

## Atlas PM WebApp v4 — 参考开源工具完全重建

### 用户反馈
1. "根本点击不了" — 所有交互失效
2. "计费平台关项目管理什么事" — 数据内容与项目管理无关
3. 要求参考全网开源项目管理工具重新开发

### 根因分析
1. **点击失效**: 旧文件 `.modal-overlay` CSS `display:flex` 与 inline `style="display:none"` 冲突; 页面 section 用 Tailwind `hidden` 类(`!important`)切换显示但未同时添加 `flex` 类导致 `flex-col` 失效; 累积的 CSS 覆盖层阻断点击
2. **内容无关**: 旧数据是"计费平台/Stripe迁移", 与项目管理无关

### 研究参考
调研 Linear、Plane、Focalboard、Jira、Asana、ClickUp、Taiga、OpenProject 后确定标准架构:
- **核心实体**: Project → Epic → Issue (含 Subtask), Sprint/Cycle 驱动
- **标准视图**: Board(看板) + List(列表) + Dashboard(仪表盘)
- **Issue属性**: Title, Status, Priority, Assignee, Labels, Due Date, Points
- **工作流**: Backlog → Todo → In Progress → In Review → Done
- **仪表盘**: 燃尽图、速率图、状态分布、活动流

### 重建内容
完全重写 `pm-webapp.html` (1228行, ~43KB JS):
- **4个项目**: 官网重构、移动端 v2.0、数据平台建设、内部工具优化
- **6位团队成员**: 陈宇(项目经理)、张明(前端)、王浩(后端)、李娜(设计)、赵雪(测试)、刘洋(DevOps)
- **18个任务**: 真实PM场景如"实现OAuth2认证流程"、"修复时间戳API超时"、"移动端虚拟滚动优化"
- **7个页面**: 仪表盘、看板、列表、我的任务、收件箱、团队、设置
- **完整CRUD**: 任务新建/编辑/删除/状态切换
- **任务详情面板**: 点击任意任务卡片打开详情, 可移动状态、编辑、删除
- **看板**: 5列看板 + 按项目筛选
- **列表**: 全任务表格 + 按优先级筛选 + 搜索
- **i18n**: 中/英双语, 默认中文

### 关键技术决策
1. **放弃 Tailwind `hidden` 类** — 用自定义 `.page { display:none }` + `.page.active { display:block }` 避免 `!important` 冲突
2. **Modal 用 classList** — `.modal-bg { display:none }` + `.modal-bg.show { display:flex }`, 不用 inline style 切换
3. **所有函数 `window.fn = fn` 显式导出** — 15个函数全部导出, 确保 onclick 可靠
4. **纯原生 JS** — 无框架依赖, 无 html2canvas, 无外部库(除 Tailwind CDN)

## Atlas PM WebApp v5 — 补全模态框CRUD函数

### 问题背景
v4重写时分段写入策略导致最后一次 Edit 匹配 `/* END MARKER */\n</script>` 失败,原因:文件末尾实际是 `/* END MARKER */\n</body>\n</html>` — 缺少 `</script>` 闭合标签。导致 `<script>` 标签从未关闭,浏览器将 `</body>` 等当作JS解析。

### 修复内容
用 Edit 匹配 `/* END MARKER */\n</body>\n</html>` 替换为 ~340行 JS + `</script>\n</body>\n</html>`,追加的函数:
1. **openIssueModal/closeIssueModal/saveIssue** — 任务新建/编辑,含 start/end/createdAt 时间戳
2. **openIssueDetail/closeIssueDetail/moveIssue/editCurrentIssue/deleteCurrentIssue** — 任务详情面板CRUD
3. **openProjectModal/closeProjectModal/selectProjectColor/saveProject** — 项目新建(6色选择)
4. **openSubAccountModal/closeSubAccountModal/saveSubAccount** — 子账号创建(手机/姓名必填,权限多选)
5. **openComposeModal/closeComposeModal/sendMessage** — 邮件发送(收件人下拉含管理员+子账号)
6. **renderAll/init** — 渲染聚合 + 初始化(DOMContentLoaded)
7. **window exports** — 25个函数显式导出

### 验证
- `node --check` 通过(exit 0)
- 本地服务器 http://localhost:3838 运行正常
- 文件总计 1534 行

### 经验教训
- 分段写入大文件时,每次 Edit 后应读取文件末尾确认标记格式,不能假设标记后面跟的是什么
- `</script>` 闭合标签缺失是隐蔽 bug,浏览器不会报错但会把后续HTML当JS执行
